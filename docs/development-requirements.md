# EventFlowOS 开发需求

更新日期：2026-09-24

## 1. 目标

EventFlowOS 需要把事项从单条记录扩展为可查询、可排序、可解释的事件上下文。系统应支持按项目和条件筛选事项，按时间顺序形成上下文，并通过 REST 与 MCP 为进一步分析、排期和建议提供结构化数据。

## 2. 功能范围

### 2.1 事项上下文

- 以项目为边界查询事项。
- 支持按关键词、状态、开始/结束时间和是否包含已完成事项筛选。
- 返回按事件时间排序的事项；排序优先级为开始时间、结束时间、日期、创建时间。
- 返回事项之间的前置和后续关系，供 Agent 生成上下文、风险和建议。
- 查询结果必须遵守当前用户的数据隔离和项目权限。

### 2.2 前置事件和后续事件

- 每个事项可以拥有零个或多个前置事项，也可以拥有零个或多个后续事项。
- 网页端应提供同项目事项的可搜索选择器，MCP 可传入事项 ID。
- 保存关系时应去重，并拒绝不存在、无权访问或指向自身的事项。
- 有向关系必须拒绝形成环；同一事项不得同时作为自己的前置和后续事项。
- 删除事项时关系应自动清理或保持数据库级一致性。
- 后续阶段可增加基于时间、项目和语义的关系候选，但不得自动覆盖人工关系。

### 2.3 活动形式

- `event_format` 允许为空、`online` 或 `offline`。
- 不支持 `hybrid`。
- 线上事项可以保存会议链接；线下事项可以保存地点信息。
- 线上事项不应保存线下地点，线下事项不应保存会议 URL；接口和数据库都必须校验。
- 活动形式为空时，不调用会议或地图解析服务。

### 2.4 腾讯会议解析

- 支持粘贴完整邀请文本或会议链接。
- 邀请原文和结构化入会链接必须分开保存；解析只生成候选，不覆盖原文或已手动填写的字段。
- 本地解析提取标题、时间、会议号、密码和入会链接。
- 可选使用只读腾讯会议 CLI（`meeting:get`）补充缺失信息。
- CLI 不可用、超时或返回错误时，保留本地解析结果并返回可解释的诊断状态。
- 解析结果只生成待确认草稿；用户可逐字段确认应用，不得未经确认直接写入事项。
- LLM 识别应是用户显式触发的补充；使用严格结构化输出，低置信字段需确认，且不得把会议密码发送到模型或日志。

### 2.5 线下地点和高德服务

- 用户可以输入地点名称或地址，显式触发高德地理编码/POI 解析。
- 保存地点名称、标准地址、POI ID、经纬度、置信度和服务来源。
- 高德 API Key 只由后端使用，不发送到浏览器、普通日志或模型上下文。
- 高德未配置、调用失败或结果不确定时，返回状态和建议，不伪造坐标。
- 路线估算支持驾车、公交、步行和骑行，并保留路线服务不可用状态。

### 2.6 排期可行性与建议

- 按时间顺序评估连续事项之间的交通时间、准备缓冲和可用间隔。
- 地点缺失、路线不可用或时间不足时，返回明确原因。
- 建议至少覆盖：调整顺序、延长间隔、改期、改为线上、确认地点。
- 建议是分析结果，不自动修改事项。

### 2.7 设置页集成配置

设置页支持用户级配置：

- 高德：启用开关、API Key、默认城市、请求超时。
- 腾讯会议 CLI：启用开关、可执行文件路径、工作目录、请求超时、允许命令白名单。
- API Key 保存后只返回是否已配置，不回显明文；留空更新时保持原值。
- REST、MCP 和飞书入口均必须使用当前用户的集成配置覆盖环境默认值。

## 3. 接口契约

### REST

- `POST /api/v1/items/parse-meeting`
- `POST /api/v1/locations/resolve`
- `POST /api/v1/calendar/assess-feasibility`
- `GET/PATCH /api/v1/preferences`

### MCP

- `pa_parse_meeting_invite`
- `pa_parse_meeting_input`
- `pa_resolve_offline_location`
- `pa_assess_schedule_feasibility`
- `pa_get_project_context`
- `pa_set_item_relations`

MCP 工具必须使用 PAT 对应用户，不得使用固定的环境用户或全局集成配置。

## 4. 数据与迁移要求

- 新字段必须通过幂等 migration 增加，迁移可重复执行。
- 事项关系使用独立关系表或等价的可约束结构，不把关系编码进备注文本。
- 地点坐标使用可安全序列化的数值类型；幂等快照不得直接写入数据库 Decimal 等不可 JSON 序列化对象。
- API 响应、日志和审计信息不得包含高德明文 Key。

## 5. 验收标准

1. 创建线上事项时可以保存 URL，切换为线下后 URL 被清理或拒绝。
2. 创建线下事项时可以保存地址，并在高德启用后解析出标准地址或 POI。
3. 同一事项可以关联多个前置和后续事项，重复关系不会重复显示。
4. 项目上下文查询能够按条件过滤，并按时间稳定排序，同时返回关系边。
5. 会议邀请在无 CLI 时仍能完成本地解析；CLI 启用时只执行白名单命令。
6. 排期评估能够报告交通时间不足、地点未解析和路线服务不可用。
7. 设置页保存后刷新不会回显高德 Key，相关 REST/MCP/飞书调用能读取用户级配置。
8. 后端测试、Ruff、Pyright、前端 lint/build、MCP 握手和生产健康检查全部通过。

- 会议邀请规则识别支持常见中英文标题、时间、会议号和密码标签、中文日期及非腾讯 HTTPS 入会链接。
